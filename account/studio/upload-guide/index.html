Storyteller Studio

Game and tool upload guide

Download template → Edit → Upload → Preview → Publish

1. Download your template

Use the Templates button at the top of Studio to download a fresh Game or Tool project without creating a draft. Select landscape (1920 × 1080) or portrait (1080 × 1920), then choose any account-save or multiplayer features before downloading the template ZIP. New, unpublished content also offers a starter in its file editor. Tools are available to admins and always publish as From A Storyteller. Multiplayer games also publish as FAS.

2. Edit in your own code editor

Extract the ZIP. Edit game.js and game.css, or tool.js and tool.css. Keep meta.json for the file names, orientation and game settings, and place media in assets/.

Open README.txt in the ZIP for the canvas helpers, save and room APIs, limits and examples. Open index.html to test the canvas locally. Use your editor’s local web server and two tabs for multiplayer demos. Local demo saves are separate from live account saves.

3. Upload the project

Choose your ZIP, its extracted folder, or the JS, CSS, metadata and media files together. Each upload replaces the complete player package, so include every asset you still need. Keep the standard file names. The site supplies the surrounding page; your local HTML and runtime are development helpers.

Use a self-contained classic JS file. Bundle any libraries into it. Uploaded players cannot load external scripts, network services or remote assets. Never include passwords, API keys or other secrets.

4. Preview before saving

Choose Preview uploaded files, then Start / restart. Check controls, canvas orientation, media and small-screen layout. Private Studio previews have no account access; use the downloaded local examples to test saves and multiplayer while developing. JS is limited to 256 KiB, CSS to 64 KiB, with up to 24 media assets of 1 MiB each and a complete package or expanded ZIP of 4 MiB.

5. Save and publish

Add a title, description, controls/instructions, category, cover with alt text and reviewed content warnings. Save a draft, then publish or schedule when ready. For published work, save live changes to update the page. Download current files whenever you want to return to your editor.

Players explicitly enable account features on the published game. Account saves must match the declared schema and version; load the latest revision before updating progress. Private multiplayer supports 2–8 players, with the host controlling shared game state. Game pages display the published package’s capabilities near the title.

Edit an existing game or tool

Open the item in Your work, or FAS-owned content for site work you can administer, then choose Download current files. Published items show their current working files rather than a fresh starter. Edit the standard JS/CSS files in your own editor and upload the complete ZIP or project folder back to that item. Preview it, then select Save updated player files. The page address and traffic history stay the same. Keep meta.json, including its template identifier, with the project.

The original four players use compatibility projects with their original controls and local-only features. To build an account-save or multiplayer game, choose Add content → Game and start with its matching template.
