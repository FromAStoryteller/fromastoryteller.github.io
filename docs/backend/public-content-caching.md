# Public website caching

Public catalogue data and rendered content pages use the Cloudflare Cache API for up to 60 seconds. Each request first reads the anonymous `fas_public_content_revision` RPC without caching. A committed change to stories, assets, profiles, roles, file publications, FAS publishing permissions, brand identity or account deletion jobs rotates that opaque token in the same database transaction. The token and build release are part of the cache key, so old entries become unreachable immediately after a publication/access change or deployment. If the revision check fails, the Worker returns 503 rather than serving an unchecked manuscript. Requests already in flight use the database state at their freshness check.

Only anonymous published projections are shared. Reader cookies and authorization headers are discarded before rendering; only the production publishable key reaches public RPCs. Drafts, account data, Studio and personalised responses do not enter this cache. The browser receives `no-store` for these dynamic responses. Error responses, redirects and responses with cookies are never stored. Diagnostic response header: `X-FAS-Public-Cache: HIT|MISS`.

`/api/public/stories` accepts only a validated catalogue cursor, and `/api/public/files` accepts no query parameters. Development and preview retain their own direct anonymous RPC path; production uses the same-origin Worker endpoints. The shared catalogue request is reused during a page visit. Published static metadata is generated into `content/catalogue.json`, replacing the index plus one request per item and a separate reading-times request.

The hosting build creates `/_assets/<dependency-hash>/...` versions of public scripts, styles, images, fonts and JSON. Each asset and its dependency graph receives a stable hash; import cycles are hashed together. Relative imports, CSS URLs and known absolute references are rewritten to those URLs. Unchanged images, fonts and modules keep their URLs across unrelated releases. Versioned scripts and styles are minified. These URLs use one-year immutable browser caching. A changed build separately rotates the dynamic-page release namespace. Frozen policy history HTML keeps its original bytes and revalidated asset references. Original URLs remain available with normal revalidation, and runtime account configuration is always unversioned and `no-store`. `content/build-release.json` is also `no-store`. The deployment audit manifest records final transformed bytes.

Signed-in homepage presentation still briefly reserves the personalised layout, but releases existing public cards after at most 1.5 seconds if authentication or discovery is slow. Normal catalogue refreshes preserve existing cards and avoid adding a loading notice over available content.

Validation: `TZ=UTC npm test`, `npm run validate:references`, `npm run validate`, `npm run build:cloudflare`, and `npx wrangler deploy --dry-run`. The Studio database suite includes invalidation and anonymous privilege tests. After release, check versioned asset headers, two sequential public requests for MISS/HIT, a current revision response, and public story/account routes. No new infrastructure subscription, privileged runtime key or external purge service is required.
