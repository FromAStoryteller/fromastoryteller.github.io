# Contributor profiles and anonymous audience insights

Released 20 October 2026. Social and website links remain in Account > Edit my profile and are inherited by public contributor bylines. Contributor profiles support square cropped JPEG/PNG photos, accessible descriptions and replacement/removal. Viewer accounts have name-only editing; server preflight, reservation and registration independently reject viewer photo uploads. Former contributors may remove an existing image. No existing profile records or photos are deleted by this release.

## Collection

The site shell loads audience-insights.mjs. It counts once per visible public profile/content identity in the current page lifetime, only after an explicit analytics choice. Prior version-1 storage choices never enable analytics. A refreshed popup asks about the new category. Essentials only and Decline disable it. Withdrawal applies synchronously when saving settings. Do Not Track and Global Privacy Control override consent. No collection runs in Studio, account pages or embedded game frames; their DOM has no public content identity.

Payload: public page UUID, profile/content kind, source group (direct/internal/search/social/other), viewport group (mobile/tablet/desktop), and consent=true. No account session, cookies, full URL, raw referrer, IP, persistent visitor identifier, game state or manuscript is sent in the analytics payload. Fetch uses credentials:omit and referrerPolicy:no-referrer. Normal provider network/security logs remain separate and are disclosed.

fas-page-view accepts only the exact environment origin and public project key (validated by the handler against the project Auth settings endpoint; supports modern publishable keys and legacy anon JWT keys). It validates a maximum 512-byte streamed body and exact dimensions, excludes known bots and caps each isolate at 600 requests/minute. This is a basic load bound, not a distributed anti-abuse guarantee. Public keys/origins cannot establish human identity; totals are approximate and can include repeated/self views or unrecognised automation. Never use these counts for payouts, billing or verified unique visitor claims. The server service credential never leaves the Edge Function.

The service-only fas_record_page_view checks the current public projection, resolves real ownership and atomically increments a daily bucket. Private drafts, hidden profiles, removed content and unknown IDs are ignored. Existing stable beneficiary attribution remains in effect across personal/FAS byline changes. There is no historical backfill. No new paid service is provisioned; existing Supabase Edge/DB usage applies.

## Reports and retention

Authenticated current contributors see only their own beneficiary's totals through fas_my_studio_traffic. Reports cover 7, 30 or 90 days: total/profile/content views, traffic groups, screen-size groups, daily UTC views and page breakdown. Per-piece entry points retain the existing Studio navigation; Edit my profile also links directly to its profile filter. CSV downloads use only visible aggregate report data. Collection dates and no-data states are explicit. Engagement/completion and ad metrics are hidden for this provider because they are not collected. No monetization is activated.

cron job fas-page-view-retention runs daily at 03:17 UTC; deletes FAS first-party report rows older than current_date-89. Existing imported provider records are unaffected. The reporting window excludes expired dates even before the next cleanup. Reports contain no per-visitor rows. After account deletion the existing beneficiary reference loses its user association, and remaining anonymous buckets expire under the same bound.

The additive contributor_audience_insights migration is tested across the complete schema plus rollback-only development fixtures. Production rollout applies the schema and Edge Function before the matching UI, publishes exact immutable contributor-insights-2026-10-20-v1 policy snapshots, verifies public bytes, then activates the guarded policy transition. Policy acceptance and analytics consent remain separate; no acceptance is fabricated. Disable collection by removing the client initializer or disabling the Edge Function; retain owner exports and report security. Monitor service usage and counts before considering stronger distributed rate limits.
