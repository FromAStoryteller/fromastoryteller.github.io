# Public discovery and browser restoration - 29 October 2026

The metadata-only file catalogue previously built complete editorial payloads twice per migrated story and discarded them. Its replacement keeps identical public output and visibility rules without loading manuscripts. A production comparison returned identical metadata; an illustrative database execution changed from 75.7 ms / 2,625 shared buffer hits to 7.8 ms / 114 hits. These are query measurements, not a guarantee of end-to-end network latency. The backwards-compatible bootstrap uses one combined RPC after the existing fresh revision check.

The new public browse query returns at most 24 cards, a cursor, count, filter facets and a bounded featured selection. Home/type filters, search suggestions, search results and related content use it rather than downloading the complete contributor catalogue. The database computes publication visibility and account/publishing eligibility for every query. Only public card metadata leaves the database; manuscripts, executable packages, owner IDs and account data do not. Reading length is computed on content writes. File-backed taxonomy and the correct cover dimensions are seeded from the source catalogue; after claiming or changing a static item, regenerate and apply `supabase/ops/file-discovery-metadata.sql` using `node scripts/generate-discovery-metadata.mjs`.

The public API validates bounded query parameters and uses anonymous requests only. Reader cookies and credentials never reach the shared query. Every cached lookup still checks the current publication revision; withdrawal, author access removal and deletion invalidate old results immediately. Browser responses remain no-store. Database helpers live in the unexposed private schema with explicit grants; the new public wrappers are security invokers. Filter queries use stable ordering with bounded offset pagination. Concurrent publication changes can move rows between pages, so the client deduplicates IDs; users can refresh a view to start a new result set.

Grid rendering creates nodes only for the displayed batch, retaining unchanged cards. Disabled, generated filter controls reserve the loading layout; carousel control space stays stable as the number of contributors changes. Dynamic canonical image paths resolve the built responsive manifest as well as versioned paths, so database-backed static cards retain AVIF/WebP delivery.

Back/Forward restores preserve the document shell and re-fetch current browsing results. Private Saved, Favourites, Following and History roots are hidden at departure and remain hidden until a fresh account connection and data read finish. Session changes cannot revive an old account's view. In-flight old controllers are ended, subscriptions are removed, expanded page counts are restored, and scroll is restored unless the visitor interacts while waiting. Content detail/profile pages retain their full visibility revalidation path. A fresh server failure does not reveal a cached private root or withdrawn restored browsing result.

`test-performance-budget-browser.mjs` tests the compiled asset graph at phone and desktop widths with synthetic latency/data. It gates initial script bytes, main-content/LCP timing, cumulative layout shift, filter response timing, true 24-node batches, pagination, search beyond the old startup page, same-document restoration and private-account restoration. These are CI regression budgets, not real-user Core Web Vitals or a visitor reporting endpoint. The PostgreSQL suite exercises 70 items, full-result filters, bounded paging, private-field denial and immediate withdrawal/role-removal behaviour.

## Policy review

The prior Privacy notice said content search happened entirely in the browser. The new paired policy release, `discovery-delivery-2026-10-29-v1`, explains that search terms and filters are processed by Cloudflare and Supabase for public discovery, may appear in URLs/provider operational logs, and are not turned into an account-linked search history or sent to a separate analytics service. It also explains public-only delivery caches and hidden/reverified private Back/Forward views. No new cookies, visitor identifiers, analytics collection, third-party tracking or contributor rights are introduced. Existing image-formatting permission already covers display derivatives. Cookie controls and contributor licence wording therefore stay unchanged.

Earlier frozen snapshots and personal agreement records remain untouched. Publish and verify the new exact snapshot bytes before applying the guarded predecessor transition in `supabase/ops/discovery-delivery-2026-10-29-v1.sql`. The transition records no acceptance for an account holder; the existing account UI obtains any required new agreement. Preserve DEV's intentionally separate policy configuration. Export, deletion and privacy requests stay available independently of accepting the new release.
